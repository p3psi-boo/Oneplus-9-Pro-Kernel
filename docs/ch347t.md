# CH347T USB 转 SPI/GPIO

一加 9 Pro 的实验内核内置沁恒 CH347T 驱动。支持 Mode 1 的 USB
`1a86:55db` 接口 `02`，不会接管 UART 或其他芯片。连接 USB OTG 转接板
后，驱动在片选 CS0 注册一个 SPI Mode 0 用户态设备。不用装 `.ko`。
此集成不启用 I²C，不修改原厂模块检查、SELinux、设备节点权限或刷机分区。

## 连接与检查

- 以实物丝印和原厂资料核对 USB 转接板模式。CC1101 需要稳定的 3.3 V
  供电与兼容的 I/O 电平；共地后连接 SCK、MOSI、MISO 与 CS0。
- 通过 Android 宿主的 USB 枚举确认 `1a86:55db`，在 sysfs 检查接口
  是否绑定到 `mphsi-ch34x`。SPI 节点是 `/dev/spidev<总线号>.0`，
  总线号随连接变化。按 USB 接口的 sysfs 父级识别目标，不能把其他
  SoC SPI 节点当成 CC1101。GPIO 节点为动态分配的 `/dev/gpiochipN`；
  其偏移 0、1、2 分别对应 GPIO4、GPIO6、GPIO7。只有固件版本
  `0x0341` 或更新且存在中断端点时驱动才启用 GPIO IRQ。
- 先读取 CC1101 的 PARTNUM、VERSION，再测已知参数的 FIFO 收发。
  用 Droidspaces 时驱动仍在 Android 宿主运行。容器只应暴露指定节点，
  并使用符合 Android SELinux 的权限。不要给全部 SPI/GPIO 节点放权。
- `rf-gatewayd` 是独立用户态服务，不包含在刷机包。FIFO 收发和遥控器
  的微秒级脉冲接收、发送是三项不同验证；GPIO 中断能工作不代表能学习。

## 源码与验证

源代码来自 [沁恒 MPHSI 1.7 固定提交](https://github.com/WCHSoftGroup/ch34x_mphsi_master_linux/tree/57be7ed01e2adb14d34bcca5e1eb71ff6247aba7)，保留其中 C 源文件的 GPL 声明。
项目新增内置 Kbuild，收窄 USB 匹配和 SPI 自动注册，并加固 USB 输入、
短中断与失败回收。固定提交、Kbuild 补丁及实际编译的文件摘要记录在
`build.json`。编译阶段核对配置和最终链接符号，发布前仍核对全部
13,797 个原厂导出符号及 CRC。编译结果不代表已验证 Android 真机启动、
热插拔、原厂模块加载或射频收发。
